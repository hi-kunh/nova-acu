# NCU 이벤트 코드 질의 — Platinum 쪽 확인 요청

> 보내는 쪽: NCU(신규 ACU) 펌웨어 개발
> 작성: 2026-09-10
> 요청: 아래 **질의 1~3**에 대한 답. 맨 끝 **회신 양식**에 채워 주시면 됩니다.

---

## 0. 배경 — 왜 묻는가

- NCU는 **기존 IDTi 보드(SSC-324)를 대체**하는 장비입니다. 그래서 **이벤트 코드를 새로 만들 수 없고,
  기존 코드표에 있는 코드만 써야 합니다.**
- NCU는 리더·입출력을 별도 보드(RRU)에 두고 **USB로 연결**합니다. SSC-324와 SSC-R4(I/O 보드)의 관계와 같은 자리입니다.
- **RRU는 릴레이를 스스로 구동하지 않습니다.** 문 열림(화재 해정 포함)은 모두 NCU가 USB로 명령합니다.
  따라서 **USB가 끊기면 화재가 나도 문을 열 수 없으므로, USB 단절을 반드시 상위에 이벤트로 알려야 합니다.**
- 화재 시 전체 개방은 DM의 정책 기능으로 처리합니다. NCU는 DM에 이벤트만 올립니다.

**입출력 구성** (SSC-324와 같은 모듈 모양, 모듈 4개)

```
모듈 1~4 각각: 카드리더 2 · 입력 6 · 출력 4 · 알람 입력 1 · 화재 입력 1
전체: 리더 8 · 입력 32 (Exit·Door·Lock 24 + 알람·화재 8) · 출력 16
```

알람·화재 입력은 **모듈마다 실제로 배선**되어 있습니다.

## 질의 1. 알람 입력은 어느 코드를 써야 합니까?

코드표에 "Alarm Detected"라는 이름의 코드가 없어 후보가 셋입니다.
세 가지 모두 DM 이벤트 해석 표에는 등록되어 있습니다.

| 발생 / 복구 코드 | 10진수 | 코드표 이름 | Platinum 화면 문구(한국어) |
|---|---|---|---|
| `0x18010111` / `0x18010112` | 402718993 / 402718994 | Sensor Detected / Restored | 센서 알람 발생 / 복구 |
| `0x18010304` / `0x18010305` | 402719492 / 402719493 | Intrusion Detected / Restored | 침입 알람 발생 / 복구 |
| `0x18010306` / `0x18010307` | 402719494 / 402719495 | Intrusion Motion Detected / Restored | 모션 알람 발생 / 복구 |

- 처음에 `0x18010306/07`로 정했으나, 화면에 **"모션 알람"** 으로 떠서 알람 입력으로는 부자연스럽다고 판단해 다시 여쭙니다.
- **기존 SSC-324는 알람 입력(SEN0_1, ALARM)을 어느 코드로 올렸는지** 알려 주시면 그대로 따르겠습니다.

## 질의 2. USB(NCU↔RRU) 단절·복구는 어느 코드를 써야 합니까?

### 2-1. 기존 보드가 쓰던 코드가 있습니까?
**SSC-324가 SSC-R4(I/O 보드)와의 연결이 끊기거나 복구될 때 올리던 이벤트**가 있다면 그 코드를 쓰는 것이 가장 맞습니다.
PC 소스(DM, Platinum, SDK)에서는 SSC-R4 연결 끊김 전용 이벤트를 찾지 못했습니다.

### 2-2. 없다면 — 후보

| 코드 | 10진수 | 코드표 이름 | Platinum 화면 문구 | 용도 |
|---|---|---|---|---|
| `0x20030102` | 537067778 | Hardware_No Response | 응답없음 | 단절 후보 |
| `0x2003010B` | 537067787 | Hardware Network (Chip) Error | 네트워크(칩) 오류 | 단절 후보 |
| **(복구)** | — | **짝이 되는 기존 코드 없음** | — | **어떤 코드를 쓸지 결정 필요** |

- 이벤트 구조의 **Module Address** 필드에 끊긴 모듈 번호를 실을 수 있습니다.
- "Hardware" 계열(`0x2003xxxx`)은 **WebApp 판본 코드표(`2. IDTi Protocol Event Structure & Event Code.doc`)에만 있고,
  SDK 판본(`IDTi Protocol Event Code.doc`)에는 없습니다.** 현재 Platinum이 이 계열을 표시하는지 확인 부탁드립니다.

### 2-3. 쓰지 않으려는 코드 — 이유

| 코드 | 코드표 이름 | 쓰지 않는 이유 |
|---|---|---|
| `0x20010101` / `0x20010102` | Comm Started / Comm Halted | **DM이 NCU와의 TCP 연결이 끊겼을 때 스스로 기록하는 코드**입니다(DM `frmMain.cs` 연결 오류 처리). USB 단절에 같은 코드를 쓰면 **"NCU가 끊긴 것"과 "NCU 안에서 RRU가 끊긴 것"을 구분할 수 없습니다** |

이 판단이 맞는지도 함께 봐 주십시오.

## 질의 3. 위 코드들이 Platinum 화면 문구와 실제로 연결되어 있습니까?

Platinum은 8자리 이벤트 코드를 소스가 아니라 **DB의 `eventcode_tbl` 표(`StringCode` 컬럼)** 로 화면 문구에 연결합니다
(`clsQuery.cs`의 `select * from eventcode_tbl order by event_type, event_object, event_code`, `clsDisplay.cs`의 `dr["StringCode"]`).
그래서 코드가 문구와 연결되어 있는지는 소스만으로는 확정할 수 없습니다.

아래 코드들이 `eventcode_tbl`에 있고, 화면 문구와 연결되어 있는지 확인 부탁드립니다.

| 코드 | 기대하는 화면 문구 | Platinum 표시 번호(enumEventStringCode) |
|---|---|---|
| `0x18010401` / `0x18010402` | 화재 알람 발생 / 복구 | 71 / 72 |
| `0x18010111` / `0x18010112` | 센서 알람 발생 / 복구 | 50 / 51 |
| `0x18010304` / `0x18010305` | 침입 알람 발생 / 복구 | 67 / 68 |
| `0x18010306` / `0x18010307` | 모션 알람 발생 / 복구 | 69 / 70 |
| `0x20030102` | 응답없음 (Hardware No Response) | 확인 필요 |
| `0x2003010B` | 네트워크(칩) 오류 | 확인 필요 |

## 참고 — 이미 정한 것

| 항목 | 내용 |
|---|---|
| 화재 입력 | `0x18010401` Fire Detected / `0x18010402` Fire Restored |
| 화재 시 전체 개방 | DM 정책으로 처리. NCU가 Fire Detected를 올리면 DM이 `devicepolicyevent_tbl` → 강제 개방 정책 → `devicepolicycontroller_tbl`의 컨트롤러마다 `ControlDoorForcedOpenModeChange`(Object 206, `Normal=0` / `ForcedOpen=1`)를 보냄 |
| 장치 종류 | `DeviceCategory=3`(Controller), `DeviceType=33`(SSC_324) |
