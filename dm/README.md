# DM ↔ NCU 문서함

> NCU(신규 ACU) 펌웨어 쪽과 IntelliScan Device Manager(서버)·Platinum 쪽이 주고받는 문서를 **이 폴더 한곳**에 모읍니다.
> 만든 날: 2026-09-11 · 앞으로 대화가 많아질 것 같아 저장소 루트에 흩어져 있던 파일을 모두 옮겼습니다.

---

## 📢 DM 쪽에 알리는 것 (2026-09-11)

1. **문서 위치가 바뀌었습니다** — 저장소 루트 → **`dm/`**. 앞으로 질의·회신·자료는 **이 폴더에** 넣어 주십시오.
   파일 이름은 그대로라 문서 안의 서로 참조(`NCU_이벤트코드_질의_회신.md` 등)는 그대로 통합니다.
2. **파일 전달 중 두 파일이 뒤바뀌었습니다** (2026-09-11 오후 회신 때)
   - `NCU_장치구조_프로토콜_안내.md` 자리에 **질의서 내용**이 들어갔고, 질의서 파일은 지워졌습니다
   - 정리해 보내 주신 장치구조 문서는 **파일 이름이 CP949로 깨진 새 파일**로 들어왔습니다
   - NCU 쪽에서 내용을 비교해 **제자리로 돌렸습니다**: 질의서 = git 원본, 장치구조 = 보내 주신 정리본 (내용 변경 없음)
   - ⇒ 한글 파일 이름을 **UTF-8로 저장**해 주시고, 받은 문서를 고칠 때는 **다른 파일에 덮어쓰지 않았는지** 한 번 확인 부탁드립니다
3. 질의 1~7 회신은 잘 받아 반영했습니다. **추가로 실측을 요청드릴 목록**은 아래 "진행 중"에 있습니다.

## 파일 규칙

| 규칙 | 내용 |
|------|------|
| 위치 | 모든 질의·회신·자료는 `dm/` |
| 질의 | `NCU_<주제>_질의.md` (NCU → DM) — Platinum 앞 질의는 `Platinum_<주제>_질의.md` |
| 회신 | **질의 파일 이름 + `_회신`** (예: `NCU_DM_질의_RRU구성_이벤트보관_회신.md`) — 새 파일로 만들고 질의 파일은 고치지 않는다 |
| 규약·안내 | `NCU_<주제>_안내.md` — 고칠 때는 문서 안에 날짜와 정정 내용을 남긴다 |
| 자료 | 표·덤프는 설명이 되는 이름으로 (`event_codes_all.csv`) |
| 인코딩 | 파일 이름·내용 모두 **UTF-8** |
| 목록 | 새 파일을 넣으면 아래 "문서 목록"에 한 줄 추가 |

## ✅ 회신 보냄 — `NCU_통보_미구현명령_2종_회신.md` (2026-09-14)

DM의 **C부류(조회 계열) 전수 점검 결과**가 11:00에 같은 파일 뒤에 추가로 도착해서, 예정대로 한 번에 회신했습니다.

**DM이 준 확정 목록** — 조회 12종을 6대에 돌린 결과 `ncu01`은 **펌웨어 1종만 성공**.
`Command 6(RequestData) / Sub 2(Read)` 방향이 통째로 비어 있다는 진단이고, **맞습니다.**

| 명령 | 프레임 |
|---|---|
| `SettingControllerBasisValueCheck` | 6 / 2 / **41** |
| `SettingControllerValueCheck` | 6 / 2 / **43** |
| `SettingInputValueCheck` | 6 / 2 / **44** |
| `SettingOutputValueCheck` | 6 / 2 / **45** |
| `SettingCardReaderValueCheck` · 알람 설정 · 경보벨/운전모드/도어모드 스케줄 · 비상도어모드 | 6 / 2 / **Object 번호 미기재** |
| 엑세스그룹 적용 받기 | SSC-324도 실패 중 — **판정 보류** |

반복 횟수는 포인트 수를 따라간다: 리더 4회 · 입력 16회 · 출력 8회 · 컨트롤러 계열 1회.
