# DM ↔ NCU 문서함

> NCU(신규 ACU) 펌웨어 쪽과 IntelliScan Device Manager(서버)·Platinum 쪽이 주고받는 문서를 **이 폴더 한곳**에 모읍니다.
> 만든 날: 2026-09-11 · 앞으로 대화가 많아질 것 같아 저장소 루트에 흩어져 있던 파일을 모두 옮겼습니다.

---

## 📢 DM 쪽에 알리는 것 (2026-09-11)

1. **문서 위치가 바뀌었습니다** — 저장소 루트 → **`dm/`**. 앞으로 질의·회신·자료는 **이 폴더에** 넣어 주십시오.
   파일 이름은 그대로라 문서 안의 서로 참조(`NCU_이벤트코드_질의_회신.md` 등)는 그대로 통합니다.
2. **파일 전달 중 두 파일이 뒤바뀌었습니다** (2026-09-11 오후 회신 때)
   - `NCU_장치구조_프로토콜_안내.md` 자리에 **질의서 내용**이 들어갔고, 질의서 파일은 지워졌습니다
   - 정리해 보내 주신 장치구조 문서는 **파일 이름이 CP949로 깨진 새 파일**로 들어왔습니다
   - NCU 쪽에서 내용을 비교해 **제자리로 돌렸습니다**: 질의서 = git 원본, 장치구조 = 보내 주신 정리본 (내용 변경 없음)
   - ⇒ 한글 파일 이름을 **UTF-8로 저장**해 주시고, 받은 문서를 고칠 때는 **다른 파일에 덮어쓰지 않았는지** 한 번 확인 부탁드립니다
3. 질의 1~7 회신은 잘 받아 반영했습니다. **추가로 실측을 요청드릴 목록**은 아래 "진행 중"에 있습니다.

## 파일 규칙

| 규칙 | 내용 |
|------|------|
| 위치 | 모든 질의·회신·자료는 `dm/` |
| 질의 | `NCU_<주제>_질의.md` (NCU → DM) — Platinum 앞 질의는 `Platinum_<주제>_질의.md` |
| 회신 | **질의 파일 이름 + `_회신`** (예: `NCU_DM_질의_RRU구성_이벤트보관_회신.md`) — 새 파일로 만들고 질의 파일은 고치지 않는다 |
| 규약·안내 | `NCU_<주제>_안내.md` — 고칠 때는 문서 안에 날짜와 정정 내용을 남긴다 |
| 자료 | 표·덤프는 설명이 되는 이름으로 (`event_codes_all.csv`) |
| 인코딩 | 파일 이름·내용 모두 **UTF-8** |
| 목록 | 새 파일을 넣으면 아래 "문서 목록"에 한 줄 추가 |

## ⏸ 회신 보류 중 — DM의 **C부류(조회 계열) 전수 점검 결과 대기** (2026-09-14)

DM이 `NCU_통보_미구현명령_2종.md`에서 *"오늘 C부류 전수 점검을 진행 중, 끝나면 **현장 SSC-324가 답하는 명령 전체 목록**을
정리해 보내겠다"* 고 알려 왔습니다. **그 목록이 NCU가 구현할 조회 명령의 확정 목록**이 되므로,
2종만 따로 회신하지 않고 **목록을 받아 한 번에 회신·구현**합니다 (사용자 지시, 2026-09-14).

**목록이 오면 회신에 담을 것** — 그때까지 잊지 않도록 여기 적어 둡니다.

| # | 내용 |
|---|------|
| 1 | 🟢 **장치구조 반영 확인 감사** — `11000000000000` / `22333333444433` / `mType 61`·`installedtype 1` / 리더 4·입력 16·출력 8 |
| 2 | **미구현 2종 구현 일정** — `SettingControllerBasisValueCheck`(6/2/**41**), `SettingInputValueCheck`(6/2/**44**). C부류 목록과 묶어서 |
| 3 | 🔴 **`ControllerBasisInfo` 전체 필드 원시 바이트 캡처 요청** (ACU03·04). Platinum 표시값 `1/5/0`은 세 개만 추린 것이라 이것 없이는 추정 구현이 된다 |
| 4 | ⚠ **"입력 설정 쓰기 7건 성공"은 사실과 다르다** — acud에는 **Object 44 핸들러가 읽기·쓰기 모두 없다**. 실제로 버렸다: <br>`09:54:36 지원하지 않는 요청 (cmd=0x05 sub=0x05 obj=0x2c) 무시`. DM이 본 "성공"은 장비 응답이 아니라 서버 기록(`userlogtbl`)의 전송 시도로 보인다 — 9/11 회신의 **"DB 설정 ≠ 장비 설정"** 과 같은 모양 |

**NCU 쪽 교차 확인 로그** (보드 192.168.0.250, DM 문서와 독립적으로 같은 결론):

```
09:52:23  지원하지 않는 요청 (cmd=0x06 sub=0x02 obj=0x29) 무시   <- Object 41
09:54:36  지원하지 않는 요청 (cmd=0x05 sub=0x05 obj=0x2c) 무시   <- Object 44 쓰기 (DM은 "성공"으로 기록)
10:01:25  지원하지 않는 요청 (cmd=0x06 sub=0x02 obj=0x29) 무시   <- 장치구조 받은 뒤에도
```

지금 acud가 답하는 것은 **History(1) · Firmware(42) · LCD(49) · MultiLanguage(165)** 넷뿐입니다.
