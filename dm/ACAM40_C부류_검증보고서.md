## 4. ACAM 판정 — 🟢 설계대로다

**12종 전부 성공, 실패 0건.** 그리고 **응답 내용이 두 갈래로 갈린다** — 이것이 C부류의 핵심이다.

| 갈래 | 명령 | 응답 |
|---|---|---|
| **서버가 답한다** | 컨트롤러 기본설정 · 컨트롤러 장치설정 · 알람 설정 · 경보벨 스케줄 | `Success` + **빈 응답** |
| **장비에 묻는다** | 카드리더 · 입력센서 · 출력릴레이 · 비상도어모드 · 스케줄 계열 | `Success` + 값 |

🔴 **"빈 응답"이 정상이다.** `DeviceCommandBaseHandler.HasNoCounterpartOnDriverDevices` 의 설계다:

> **값을 지어내지 않는다.** 빈 DTO 를 돌려주면 Platinum 이 자기 테이블에 저장해
> "설정을 읽어 온 것처럼" 보이게 된다. 실제로는 없는 값이므로 **운영자를 속이는 셈**이다.

ACAM 은 컨트롤러 기본설정·듀레스·엘리베이터 같은 개념이 아예 없고, 구성은 **서버가 소유**한다(§110).
그래서 물어볼 이유가 없고, 물어봐야 우리가 써 넣은 값이 돌아올 뿐이다.

⇒ **ACAM 은 C부류 통과.** 에러창 없음, 없는 값이 DB 에 들어가지 않음.

## 5. IDTi 판정 — 🟢 11종 통과 · 🟡 1종은 "데이터 없음"으로 보인다

### 5-1 되읽기가 **쓴 값을 그대로** 돌려준다

```
알람 설정 받기
  ACU04  3/00:00 ~ 00:00/0/2/0/2/2/0/…    ← 09-11 14:44:02 에 쓴 값과 한 글자도 다르지 않다
  ACU03  3/00:00 ~ 00:00/0/0/0/2/2/0/…    ← 09-11 14:43:50 에 쓴 값과 동일

컨트롤러 장치설정 받기
  ACU03·ACU04 모두  3//255/0/255/11111000/11111111/11100000/11111110   (두 대가 동일)
```

⇒ **B부류 기준("되읽은 값이 보낸 값·DB 와 일치")도 함께 충족했다.**

### 5-2 🟡 유일한 실패 — `00ba` 엑세스그룹 적용 받기

```
ACU04  [2:0:0] × 4건 전부 실패
ACU03  [3:0:0] × 4건 전부 실패
ACAM 3대는 8건씩 전부 성공
```

**결함으로 보지 않는 이유:**

핸들러는 장비에서 엑세스그룹을 읽어 파싱에 실패하면 `Fail_System` 을 돌려준다
(`GroupAccessGroupCheckHandler.cs:45`). 그리고 이 프로토콜에서 **`Fail_System` 은
"그 자리에 데이터가 없다"를 뜻하는 정상 응답**이다 — §219·§220 에서 사용자 조회로 확인된 규칙이다.

```
ACAM 3대  §205·§206 시험 때 엑세스그룹을 실제로 내려보냈다  →  장비에 있다  →  Success
IDTi 2대  이 사무실 시험 장비다. 엑세스그룹을 내려보낸 적이 없다  →  없다  →  Fail_System
```

🟡 **확정하려면:** IDTi 한 대에 엑세스그룹을 한 번 전송한 뒤 다시 받아 본다.
그때 `Success` 가 나오면 "데이터 없음"이 확정되고, 그래도 실패하면 그때 결함으로 본다.

## 6. ncu01 판정 — 🔴 **조회 방향이 통째로 비어 있다**

```
🟢 성공  007c  컨트롤러 펌웨어 확인          (+ 장치구조 다운로드는 별도로 성공 확인됨)
```

통신은 정상이다 — `commstatus 0`, 폴링이 계속 갱신된다. **명령에 답을 못 하는 것이다.**

### 왜 중요한가

Platinum 의 「장치 정보 업데이트」는 이 12종을 **한꺼번에** 보낸다.
**하나라도 실패하면 그 화면 전체가 실패로 보이고**, 운영자는 "장비가 고장 났다"고 읽는다.
대체가 목표라면 **현장 SSC-324 가 답하는 명령은 NCU 도 답해야 한다.**

## 부록 — 판정에 쓴 조회

```sql
-- 명령 × 컨트롤러 × 성공여부
SELECT SUBSTRING(logcodecol,5,4) code,
       CASE WHEN CHARINDEX('[',datacol)=1 THEN SUBSTRING(datacol,2,CHARINDEX(':',datacol)-2)
            WHEN CHARINDEX('|',datacol)>0 THEN LEFT(datacol,CHARINDEX('|',datacol)-1)
            ELSE datacol END AS ctrl,
       RIGHT(logcodecol,2) rst, COUNT(*) n
FROM   userlogtbl
WHERE  datetimecol > '<시작시각>'
GROUP  BY 1,2,3 ORDER BY 1,2,3;
```

`logcodecol` = `03 0X 00CC RR` — `CC` 가 `clsConst.LogCode`, `RR` 이 `01 성공 / 02 실패`.
`datacol` 의 `[컨트롤러:모듈:리더]` 로 대상까지 갈린다.
