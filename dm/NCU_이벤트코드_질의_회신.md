## 0. 🔴 판단 기준 — **대체(replacement)** 다. 개선이 아니다

NCU 의 목표는 **기존 IDTi 장비(SSC-324)를 그 자리에 그대로 갈아 끼우는 것**이다.
서버(DM)·관리프로그램(Platinum)·현장 운영 절차는 **하나도 바꾸지 않는 것이 성공**이다.
그래서 이벤트 코드를 고를 때 순서는 이렇다:

```
① SSC-324 가 실제로 올리는 값이 있으면  → 그 값을 쓴다.  "더 자연스러운 이름"을 찾지 않는다
② 실측값이 없으면                        → 기존 어휘(987개) 안에서 고른다
③ 새 코드·새 문구는 만들지 않는다         → 문구는 Platinum 리소스에 박혀 있어 재빌드가 필요하다
```

🔴 **①이 ②보다 언제나 앞선다.** 화면 문구가 어색해 보여도 마찬가지다 —
어색함은 지금 현장이 이미 쓰고 있는 어색함이고, 그것까지 같아야 대체다.

🔴 **코드 한 글자가 기능을 가른다.** DM 의 정책 엔진은 이벤트 코드 8자리를
`devicepolicyevent_tbl.eventcode` 와 **문자열 정확 일치**로 찾는다(`DeviceRepository.cs:245`).
화재 시 전체 개방처럼 "이벤트가 방아쇠인" 기능은 **코드가 다르면 그냥 안 돈다.**

> 🟡 참고 — 지금 이 현장의 `devicepolicyevent_tbl` 은 **비어 있다.**
> 화재→전체개방 정책은 DM 에 기능은 있으나 **아직 설정돼 있지 않다.**
> 설정할 때 거기 적히는 코드와 NCU 가 올리는 코드가 **글자 단위로 같아야** 한다.

## 회신 양식 (요약)

| 질의 | 답 |
|---|---|
| 1. 알람 발생 코드 | **`0x18010306`** — 실장비 SSC-324 실측. 용도 `0`·`2` 어느 쪽이든 같은 값으로 **확정**(2026-09-11) |
| 1. 알람 복구 코드 | **`0x18010307`** (같은 근거) |
| (추가) 화재 코드 | **`0x18010401` / `0x18010402`** — 입력 용도를 `3 = Fire` 로 주면 실제로 올라온다. **NCU 가 정하신 값 그대로** |
| (추가) 🔴 주소 규칙 | **화재는 입력 슬롯이 아니라 "연동 출력(문)" 주소로 올라온다.** 알람은 입력 슬롯 주소 — 1절 끝 |
| 2-1. SSC-R4 끊김/복구 전용 이벤트 | **전용 코드는 없다.** 대신 **`0x2003xxxx` H/W Packet 계열 11종**이 그 자리다 |
| 2. USB 단절 코드 | **`0x20030102`** (H/W No Response · 화면 "응답없음") — 🟢 Platinum 코드표에 **있다** |
| 2. USB 복구 코드 | **올리지 않습니다.** 통신 계열에는 복구 코드가 없고, 기존 장비도 복구를 올리지 않습니다 — 2-3 |
| 2-3. Comm Started/Halted 를 안 쓰는 판단 | **맞습니다.** 그리고 `0x20010101`(Comm Started)은 **코드표에 아예 없습니다** |
| 3. 코드↔문구 연결 | **여섯 코드 전부 연결돼 있습니다.** 표시번호도 보내주신 값과 전부 일치합니다 |

## 1. 알람 입력 코드 — 실장비가 이미 답을 갖고 있었습니다

### 🟢 실측 결과 (오늘 2026-09-10, 현장 ACU04 = 실물 SSC-324)

```
eventlog_tbl
  18010306  controllerid 2  module 1  slot 13   16:11:56
  18010307  controllerid 2  module 1  slot 13   16:11:56
  18010306  controllerid 2  module 2  slot 13   16:08:12 / 16:08:13
  18010307  controllerid 2  module 2  slot 13   16:08:12 / 16:08:13
```

**슬롯 13 은 두 공통 입력 중 첫 번째** — 보내주신 배치의 "알람 입력"과 같은 자리입니다.
⇒ **SSC-324 는 그 입력에 `0x18010306` / `0x18010307` 을 씁니다.**

🔴 **이 값이 장비가 올린 것임을 확인했습니다.** DM 이 스스로 만들어 넣는 합성 이벤트는
`20010102`(연결 끊김)와 `20020102`(통신 오류) **둘뿐**입니다(`PollingService.cs:1478`).
`1801xxxx` 는 전부 장비에서 올라온 것입니다.

### 🔴 다만 — **코드가 "용도 설정"에 따라 갈릴 수 있습니다**

측정 당시 그 슬롯의 용도는 **`0 = 적용 안함`** 이었습니다(`inputsensor_activesetup`).

용도는 서버가 입력마다 내려보내는 값이고, 정의는 `clsDevParams.InputApplicationType` 입니다:

```
0 None(적용 안함)   1 ExitButton(출구버튼)   2 Alarm(알람)      3 Fire(화재)
4 LockStatus(잠금)  5 DoorStatus(도어)       6 Intrusion(침입)  7 LockDown
8 TamperSwitch      9 LowBattery             10 ACPower
```

즉 지금 실측값은 **"용도 미지정 입력에 대한 SSC-324 의 기본 코드"** 입니다.
용도를 `2 = Alarm` 으로 지정했을 때도 같은 코드인지는 **아직 확인되지 않았습니다.**

### 🟢 슬롯 13 = 알람, 슬롯 14 = 화재 — **DB 설정으로 확인됐습니다**

다른 실장비 **ACU03** 은 그 두 칸에 용도가 이미 지정돼 있습니다(2026-08-21 설정):

```
ACU03  모듈1 슬롯13 → 용도 2 = Alarm      모듈1 슬롯14 → 용도 3 = Fire
       모듈2 슬롯13 → 용도 2 = Alarm      모듈2 슬롯14 → 용도 3 = Fire
```

⇒ **보내주신 배치 해석(모듈당 알람 1 + 화재 1)이 맞습니다.** 순서도 알람이 먼저입니다.
(측정이 나온 ACU04 는 아직 그 두 칸이 `0 = 적용 안함` 입니다.)

🔴 **정정(2026-09-11)** — 앞선 판본에서 저희가 이 두 칸을 *"보드 전체에 2개인데 모듈마다 중복 표시된다"*
고 적었는데 **틀렸습니다.** 질의서에 쓰신 대로 **모듈마다 알람 1 · 화재 1 이 실제로 따로 배선**돼 있습니다.

```
한 모듈 = 물리 입력 6 + 알람 1 + 화재 1 = 8칸   → 전부 실물
SSC-324(2모듈) 입력 16 · NCU(4모듈) 입력 32     → 중복도 사본도 없다
```

⇒ 이벤트는 **자기 모듈 주소로 올리면 됩니다.** "어느 모듈로 올릴까"는 애초에 고민거리가 아니었습니다.

### 🟢 확정 실험 완료 (2026-09-11 14:45) — **용도가 코드를 정합니다**

Platinum 에서 입력 **용도**를 주고 실장비 SSC-324(ACU04)를 눌러 실측했습니다.

| 입력 용도 | 이벤트 코드 | 화면 문구 |
|---|---|---|
| `0` 적용 안함 | `18010306` / `18010307` | 모션 알람 발생 / 복구 |
| **`2` Alarm** | **`18010306` / `18010307`** | 모션 알람 발생 / 복구 |
| **`3` Fire** | **`18010401` / `18010402`** | **화재 알람 발생 / 복구** |

🟢 **알람은 용도 0 이든 2 든 같은 코드입니다** ⇒ 위 회신(`18010306/07`)이 확정됐습니다.
🟢 **화재는 `18010401/02` 가 맞습니다** ⇒ NCU 가 이미 정하신 값 그대로 가시면 됩니다.

> 앞선 판본에서 *"슬롯14가 한 번도 안 올라온다"* 고 적었던 것은 **그때 용도가 `0` 이었기 때문**입니다.
> 장비의 한계가 아니었습니다. 판단을 성급하게 적어 혼선을 드렸습니다.

### 🔴 그런데 화재 이벤트의 **주소 규칙이 알람과 다릅니다**

```
알람(슬롯13)   모듈1 슬롯13 → 이벤트 (1,13)     모듈2 슬롯13 → 이벤트 (2,13)    = 입력 슬롯 주소
화재(슬롯14)   모듈1 슬롯14 → 이벤트 (1, 2)     모듈2 슬롯14 → 이벤트 (2, 1)    = ❗반응 출력 주소
                             반응출력 (1,2) ─┘                 반응출력 (2,1) ─┘
```

두 모듈의 반응 출력 값이 서로 달랐는데(`(1,2)` vs `(2,1)`) **이벤트 주소가 각각 그 값과 정확히 일치**했습니다.
⇒ **화재는 입력점이 아니라 "연동된 출력(= 문)" 주소로 보고됩니다.**

🟡 표본이 두 모듈뿐이라 **반응 출력을 다른 값으로 바꿔 한 번 더 재고** 확정하겠습니다.
**NCU 도 이 규칙을 따라야 하므로**, 확정되면 바로 알려드리겠습니다.

### 📌 확정 실험 — **ACU03 을 그냥 눌러 보면 됩니다**

설정을 바꿀 필요가 없습니다. ACU03 은 **현장이 실제로 쓰는 설정 그대로** 되어 있습니다.

```
① ACU03 모듈1 슬롯13(용도 Alarm) 입력을 동작 → 어떤 코드가 오나
② ACU03 모듈1 슬롯14(용도 Fire)  입력을 동작 → 어떤 코드가 오나
③ eventlog_tbl 에서 확인
```

이걸 저희 쪽에서 돌려 결과를 바로 알려드리겠습니다.
**용도 Alarm 에서도 `18010306/07` 이면 그대로 확정**이고, 다른 코드가 나오면 **그 값이 답**입니다.
어느 쪽이든 "우리가 고른 값"이 아니라 **"기존 장비가 쓰는 값"** 이 됩니다(0절 ①).

### 🔴 "모션 알람으로 떠서 부자연스럽다" — 그래도 그대로 갑니다

처음에 `18010306/07` 로 정하셨다가 화면 문구 때문에 다시 물으신 것으로 압니다.
**0절 기준으로 보면 그 첫 판단이 맞습니다.**

- 지금 현장의 SSC-324 가 그 코드로 올리고 있고, 운영자는 이미 그 화면을 보고 있습니다.
- NCU 로 갈아 끼운 뒤 문구가 "센서 알람"으로 바뀌면 **같은 배선에서 다른 이름이 뜹니다.**
  섞여 도는 기간(한 현장에 SSC-324 와 NCU 가 함께 있는 기간)에는 **같은 알람이 두 이름으로 보입니다.**
- 이벤트 코드로 거는 정책·검색·리포트가 있으면 **코드가 달라지는 순간 안 걸립니다**(0절 🔴).

⇒ **`18010306` / `18010307` 로 갑니다.** 문구가 마음에 안 드는 것은 별도 과제로 남기고,
바꾸려면 Platinum 리소스를 고쳐 **전체 현장에 같이 적용**해야 합니다(장비 쪽에서 우회하지 않습니다).

## 2. USB(NCU↔RRU) 단절·복구

### 2-1. 전용 코드는 없습니다. 그런데 **자리는 이미 있습니다**

코드표를 통째로 훑었습니다. SSC-R4 연결 전용 이벤트는 없습니다.
대신 **`0x2003xxxx` H/W Packet 계열이 `0x2002xxxx` S/W Packet 계열과 완전히 대칭**입니다:

```
20 02 xx  S/W Packet   ← 서버(PC) ↔ 컨트롤러  사이의 통신 실패
20 03 xx  H/W Packet   ← 컨트롤러 ↔ 하위 하드웨어 사이의 통신 실패    ← NCU↔RRU 가 이 자리
```

| 코드 | 이름 | | 코드 | 이름 |
|---|---|---|---|---|
| `20030101` | H/W Frame Error | | `20030107` | H/W Checksum Error |
| **`20030102`** | **H/W No Response** | | `20030108` | H/W ETX Error |
| `20030103` | H/W Not Enough Data | | `20030109` | H/W DateTime Error |
| `20030104` | H/W Data Size Error | | `2003010A` | H/W Command Error |
| `20030105` | H/W STX Error | | **`2003010B`** | **H/W Network(Chip) Error** |
| `20030106` | H/W Length Error | | | |

🟡 현장 로그에는 `2003xxxx` 가 **0건**입니다 — SSC-324 가 실제로 올린 적은 없습니다
(그런 일이 없었는지, 안 올리는지는 가릴 수 없습니다).

### 2-2. 단절 코드 — **`0x20030102` 를 권합니다**

- 화면 문구 **"응답없음"**. 표시번호 107.
- 🟢 **Platinum 코드표에 있습니다.** "WebApp 판본에만 있는 것 아니냐"는 우려는 사실이 아닙니다 —
  `ISPDB.mdb` 의 `eventerrorcode_tbl` 에 있고 `evnet_enable=True`, `event_displayenable=True`,
  `event_storemode=2`(저장) 입니다.
- `2003010B`(네트워크(칩) 오류)는 **칩 자체의 오류**를 뜻하므로, 케이블이 빠진 경우까지 포함하는
  단절에는 `20030102` 가 더 맞습니다. **칩 오류를 따로 구분할 수 있다면** 둘을 나눠 쓰셔도 좋습니다.
- 이벤트의 **Module Address 필드에 끊긴 모듈 번호**를 실으시는 계획은 그대로 맞습니다.

### 2-3. 🔴 복구 코드 — **통신 계열에는 없습니다. 올리지 않는 것이 답입니다**

⚠️ **혼동하기 쉬운 자리라 분명히 적습니다:**

```
알람 계열 (1801xxxx)   발생/복구가 전부 쌍으로 있다
                        18010306/07 모션 · 18010111/12 센서 · 18010304/05 침입 · 18010401/02 화재
통신 계열 (20xxxxxx)   발생만 있다. 복구 코드가 하나도 없다
                        20010102 연결끊김 · 20020102 S/W 응답없음 · 20030102 H/W 응답없음  ← 전부 짝 없음
```

**"복구 코드가 없다"는 것은 통신 계열(= USB 단절) 얘기입니다.** 알람 쪽은 짝이 다 있습니다.

그래서 USB 복구는 **올리지 않는 것**이 기존 장비와 같은 처신입니다:

- SSC-324 도 통신 실패에 복구 이벤트를 올리지 않습니다(현장 로그 `20010102`·`20020102` 수천 건에 짝이 없습니다).
- DM 은 **폴링으로 현재 상태를 압니다** — 복구는 "다음 폴링이 성공한다"로 드러납니다.
- 복구를 다른 계열(`18010112` 센서 알람 복구 등)에서 빌려오면 **화면에 "센서 알람 복구"로 떠서**
  운영자가 USB 와 무관한 사건으로 읽습니다. 대체 목적에 어긋납니다.

🟡 복구 시각이 운영상 꼭 필요하다고 판단되면, 그건 **장비에서 우회할 문제가 아니라**
Platinum 어휘에 복구 코드를 추가하는 과제입니다(재빌드 필요). 그때까지는 올리지 않습니다.

### 2-4. Comm Started / Halted 판단 — **맞습니다. 그리고 한 가지 정정**

```
0x20010101  Comm Started    ← 🔴 코드표에 **아예 없습니다**
0x20010102  Disconnected    ← 있습니다. 문구 "연결 끊김", 표시번호 89
```

그리고 `20010102` 는 **DM 이 직접 만들어 넣습니다** — 폴링이 `ConnectError` 를 만나면
DM 이 그 코드를 `eventlog_tbl` 에 넣습니다(`PollingService.cs:1478`, 그 밖의 통신 오류는 `20020102`).

⇒ **NCU 가 이 코드를 올리면 "NCU 가 끊긴 것"과 구분할 수 없습니다. 쓰지 않으시는 판단이 정확합니다.**

## 3. 코드 ↔ 화면 문구 연결 — **여섯 전부 연결돼 있습니다**

`ISPDB.mdb` 실덤프로 확인했습니다. **표시번호가 보내주신 값과 하나도 어긋나지 않습니다.**

| 코드 | 코드표 이름 | 표시번호 | 화면 문구(한국어) | 보내주신 기대값 |
|---|---|---:|---|---|
| `18010401` | Fire Detected | **71** | 화재 알람 발생 | 71 ✅ |
| `18010402` | Fire Restored | **72** | 화재 알람 복구 | 72 ✅ |
| `18010111` | Sensor Detection | **50** | 센서 알람 발생 | 50 ✅ |
| `18010112` | Sensor Restoration | **51** | 센서 알람 복구 | 51 ✅ |
| `18010304` | Intrusion Detected | **67** | 침입 알람 발생 | 67 ✅ |
| `18010305` | Intrusion Restored | **68** | 침입 알람 복구 | 68 ✅ |
| `18010306` | Motion Detected | **69** | 모션 알람 발생 | 69 ✅ |
| `18010307` | Motion Restored | **70** | 모션 알람 복구 | 70 ✅ |
| `20030102` | H/W No Response | **107** | **응답없음** | (확인 필요) → 확인됨 |
| `2003010B` | H/W Network(Chip) Error | **116** | **네트워크(칩) 오류** | (확인 필요) → 확인됨 |

전부 `evnet_enable=True` · `event_displayenable=True` · `event_storemode=2`(저장) 입니다.

### 📌 한 가지 정정 — 연결 구조

질의서에 *"Platinum 은 `eventcode_tbl`(StringCode 컬럼)로 문구에 연결한다"* 고 적으셨는데,
실제로는 **4단 계층**이고 8자리 전체를 맞추는 것은 **맨 아래 표**입니다:

```
eventtype_tbl        Type   (01 Access · 10 Data · 18 System · 20 Communication)
eventobject_tbl      Object
eventcode_tbl        Code
eventerrorcode_tbl   ErrorCode   ← 여기서 8자리 전체가 결정된다. 여기 없으면 문구가 안 뜬다
```

그리고 `event_strcode` 는 **번호일 뿐**이고, 실제 문자열은 Platinum 의 언어 리소스
(`resEventCode.ko-KR.resx` 등)에 있습니다. ⇒ **새 문구를 만들려면 Platinum 재빌드가 필요합니다.**
**기존 어휘 안에서 고르는 것이 답**인 이유가 이것입니다.

🟡 미정의 코드를 올려도 Platinum 은 숫자를 그대로 보여줍니다(에러는 아닙니다).
**"이름이 안 뜬다 = 형식이 틀렸다" 가 아닙니다.**

## 5. 저희가 이어서 할 것

```
🔴 질의 1 확정 실험 — ACU03(용도가 이미 Alarm/Fire 로 잡혀 있다) 슬롯13·14 를 눌러 코드 확인 → 회신
🟡 그 결과로 용도별(ExitButton/Alarm/Fire/LockStatus/DoorStatus/…) 코드 매핑표를 떠 드리겠습니다
```

용도별 매핑이 정리되면 NCU 는 **"입력 용도 → 이벤트 코드"** 규칙만 따르면 되고,
알람·화재를 따로 하드코딩하지 않아도 됩니다.
**그 표는 저희가 만드는 것이 아니라 SSC-324 에서 떠 오는 것**입니다(0절 ①).

## 6. 앞으로 이런 질문이 나올 때 — 저희에게 물어 주십시오

"어느 코드를 쓰는 게 맞나"는 **문서가 아니라 실장비 로그가 답하는 질문**입니다.
이번에도 코드표 후보 셋을 놓고 고민하셨는데, 현장 로그에 **이미 찍혀 있었습니다.**

현장에는 SSC-324 두 대(ACU03·ACU04)가 살아 있고 저희가 이벤트 로그를 바로 조회할 수 있습니다.
**"이 상황에서 SSC-324 는 어느 코드를 올립니까?"** 로 물어 주시면 실측해서 답하겠습니다.
그게 대체 목적에 가장 빠른 길입니다.
