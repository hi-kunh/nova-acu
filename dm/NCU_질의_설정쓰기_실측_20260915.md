## 1. 🟢 입력·출력 쓰기 — 실제 DM으로 성공

| 시각 | 명령 | NCU 처리 | 설정 성공 이벤트 |
|---|---|---|---|
| 13:34:52 | 입력 (모듈 1, 칸 3) | 저장 — 퇴실버튼, 반응 장치 칸 9 | `10210301` (1, 3) ✅ DM이 가져감 |
| 13:35:08 | 출력 (모듈 1, 칸 9) | 저장 — 동작 종류 1(Door), 5초 | `10220301` (1, 9) ✅ DM이 가져감 |

9/14 DM 회신의 원칙대로 **설정 성공 이벤트는 저장에 성공했을 때만** 올립니다.
DM 화면에 이 두 이벤트가 보이는지 확인 부탁드립니다.

---

## 2. 🟢 조회 명령 — 11종 구현, 주소 방식은 실제 트래픽에서 확정

「장치 정보 업데이트」를 세 번 눌러 봤습니다.

| 차수 | 걸린 시간 | 비고 |
|---|---:|---|
| 1차 | 180초 | 미구현 명령에 무응답 — 요청마다 DM이 약 7초 대기 |
| 2차 | 17초 | 미구현 명령에 **실패 ACK** (9/14에 물었던 "무응답 vs 실패 ACK"의 답을 실측으로 정했습니다) |
| 3차 | 16.9초 | 11종 구현 후. 미구현은 `0xA6` 그룹 적용 4건만 |

**주소 방식 (실제 트래픽):**

| 단위 | 모듈 / 비트맵 | 명령 |
|---|---|---|
| 컨트롤러 | 0 / 0 | `0x29` `0x2B` `0x51` `0x52` (`0x53` 한 번) |
| 리더 | 1·2 / bit 0·1 | `0x2F` (`0x53` 네 번) |
| 입력 | 1·2 / bit 2~7·12·13 | `0x2C` |
| 출력 | 1·2 / bit 8~11 | `0x2D` `0x54` |
| (비트맵 아님) | 0 / 0 + **데이터 9byte** | `0xA6` |

⇒ **비트 번호 = 모듈 14칸 배치(`22333333444433`)의 자리 번호**입니다. 입력 16·출력 8·리더 4회가 한 건도
빠짐없이 그 자리로 왔습니다. **9/14에 부탁드린 "입력 1~16 훑기 대응표"는 이제 만들지 않으셔도 됩니다.**

## 3. 🔴 카드리더 설정 쓰기 — 데이터가 0byte로 옵니다

DM에서 ncu01 카드리더 설정을 실행하셨을 때 NCU가 받은 것입니다.

```
13:34:06  Cmd 5 / Sub 5 / Obj 0x2F   -> Fail (데이터가 짧다)
13:41:29  Cmd 5 / Sub 5 / Obj 0x2F   -> Fail (데이터가 짧다)
          받은 데이터 0byte   모듈=1   비트맵=00000001 (리더 1)
```

**주소는 맞게 왔는데 데이터가 없습니다.** 프레임 길이에서 계산하면 헤더(44) + 꼬리뿐인 프레임입니다.

NCU는 카드리더 설정을 **32byte**로 기대합니다 — `isldev\\clsDevDeviceSetting.cs`의 Proximity 필드 합이고,
DM 소스 사본(`DeveiceManager/Source/isldev`)도 같습니다.
```
Type 1 · Wiegand 1 · AccessOption 4 · ReactionModule 1 · ReactionDevice 1 ·
Reserved 7 · Level 1 · LocalAPBLinkReader 8 · Reserved 8   = 32
```

빈 설정을 성공으로 받으면 9/14에 경고하신 **"거짓 성공"** 이 되므로, NCU는 **실패로 답했습니다.**

### 🙏 여쭙니다

| # | 질문 |
|---|---|
| 1 | DM이 카드리더 설정을 보낼 때 **데이터가 비는 것이 정상입니까?** (예: ncu01의 리더 설정이 DM DB에 아직 없어서) |
| 2 | 같은 설정을 **현장 SSC-324(ACU03·04)에 보낼 때는 몇 byte**가 나갑니까? 가능하면 **요청·응답 원시 바이트** 부탁드립니다 |
| 3 | SSC-324는 **데이터 0byte 카드리더 설정에 무엇으로 답합니까?** (성공 / 실패) — 같게 맞추겠습니다 |

## 4. 캡처 요청 정리 (9/14 목록 갱신)

| 요청 | 상태 |
|---|---|
| 1·2·3순위 원시 바이트 (`0x29`·`0x2C`·`0x2D`) | ✅ 받음 — byte 단위로 일치 확인 |
| `AddressDestBroadcast` 비트 대응표 | ✅ **필요 없어짐** — 실제 트래픽으로 확정 |
| 4·5순위 `0x2B`·`0x2F` | 🙏 여전히 부탁드립니다 — 크기를 SDK로 잡았습니다(24·32byte). **캡처로 확인하고 싶습니다** |
| 🆕 카드리더 **쓰기** 원시 바이트 (SSC-324) | 🙏 3절 |
| 🆕 설정 조회 **Fail 응답** 원시 바이트 | 🙏 `0xA6`가 SSC-324에서도 실패하니 그 응답으로 떠 주시면 Fail 형식을 맞추겠습니다 |
| 이벤트 개수·인덱스·리셋 실측 (#3) | 🙏 NCU는 되돌릴 수 있는 쪽으로 구현해 두었습니다 (개수 = 미전송, 리셋 = 보낸 것으로 표시, 인덱스 = 타입 3만) |
