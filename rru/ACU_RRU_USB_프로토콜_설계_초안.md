# ACU ↔ RRU USB 프로토콜 — 설계 초안 v0.2

> 쓴 쪽: ACU(NCU) 펌웨어 · 작성 2026-09-14
> 받는 쪽: **RRU 펌웨어 (STM32C562)**
> 상태: **초안.** RRU 개발보드 도착 전이라 실측이 없다 — 10절 "확인이 필요한 것"을 먼저 봐 주십시오.

| 판 | 날짜 | 내용 |
|---|---|---|
| v0.1 | 2026-09-14 | 첫 초안 — 프레임·식별·이벤트·출력·생존 확인 |
| **v0.2** | 2026-09-14 | 구현에 필요한 것 추가 — **상태 기계 · 타이밍 표 · 오류 처리 · 메시지별 byte 예시 · 참조 코드 · 적합성 확인 목록**.<br>프레임 규칙과 참조 코드는 `tools/rru_proto_check.c`로 검산했습니다 |

**이 문서 하나로 RRU 펌웨어를 짤 수 있는 것을 목표로 합니다.** 부족한 부분이 있으면 알려 주십시오.

## 0. 한 장 요약

```
[DM/Platinum] --TCP/IDTi--> [ACU (RK3566, Linux)] --USB CDC-ACM--> [RRU x 최대 7대]
                                                                    Wiegand 리더 · 입력 · 출력
```

- **판단은 전부 ACU가 한다.** RRU는 **눈과 손**이다 — 읽은 것을 올리고, 시킨 것을 한다
- RRU는 **릴레이를 스스로 움직이지 않는다** (2026-09-10 확정). 문 열기도 알람 릴레이도 ACU가 명령한다
- 링크는 **USB CDC-ACM**. RRU마다 `/dev/ttyACM*` 노드가 하나씩 생긴다
- **RRU가 먼저 보낸다** (카드·입력 변화). ACU가 물어볼 때까지 기다리지 않는다
- 끊겼다 다시 붙는 것을 **정상 동작으로 전제한다** — 릴레이 EMI로 USB 재열거가 실제로 일어날 수 있다

---

## 1. 왜 이렇게 설계하는가

| 전제 | 근거 |
|------|------|
| ACU 1 : RRU 여러 대 (최대 7) | 프로토콜 모듈 14칸 한계, RRU 번호 하나 = 모듈 2칸 |
| 같은 함체 안 | 케이블 짧음, RS-232 필요 없음 |
| USB CDC-ACM | STM32C562에 네이티브 USB Device가 있어 브릿지 IC 불필요 |
| RRU 자체 전원 | 리더 8 + 릴레이 8은 USB 500mA로 불가 — **신호선만 쓴다** |
| 프레임에 장치 주소 없음 | USB 노드가 RRU를 구분한다. 대신 **연결 직후 DIP 번호를 받는다** |

⚠ **릴레이가 유도성 부하라 EMI로 USB 재열거가 날 수 있다.** 그래서 프로토콜이
**끊김·재연결·재전송을 처음부터 다룬다.** 이게 이 설계의 가장 중요한 제약이다.

## 2. 프레임

```
+------+------+------+--------+---------+--------+------+
| STX  | LEN  | SEQ  | TYPE   | PAYLOAD |  CRC16 | ETX  |
| 0x02 |  2   |  1   |   1    |    N    |    2   | 0x03 |
+------+------+------+--------+---------+--------+------+
         ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
         LEN이 세는 범위 = SEQ + TYPE + PAYLOAD
```

| 자리 | 크기 | 내용 |
|------|-----:|------|
| `STX` | 1 | `0x02` 고정 |
| `LEN` | 2 | **빅엔디언.** `SEQ + TYPE + PAYLOAD`의 byte 수 (= 2 + N) |
| `SEQ` | 1 | 0~255 순환. 보내는 쪽이 매긴다. **응답은 요청의 SEQ를 그대로 되돌린다** |
| `TYPE` | 1 | 아래 표 |
| `PAYLOAD` | N | TYPE마다 다름 |
| `CRC16` | 2 | **빅엔디언.** CRC-16/CCITT-FALSE (init `0xFFFF`, poly `0x1021`), `SEQ`부터 `PAYLOAD` 끝까지 |
| `ETX` | 1 | `0x03` 고정 |

- **최대 PAYLOAD 255byte.** 지금 필요한 가장 큰 프레임이 40byte 안쪽이라 여유가 크다
- 숫자는 전부 **빅엔디언**으로 통일한다 (IDTi 규약이 빅엔디언이라 ACU 쪽 변환이 줄어든다)
- `STX`/`ETX`가 PAYLOAD에 나올 수 있다 — **바이트 스터핑을 쓰지 않고 `LEN`으로 자른다.**
  받는 쪽은 `STX` → `LEN` → 그만큼 읽기 → `CRC`·`ETX` 확인 순서로 동작하고,
  틀리면 **버리고 다음 `STX`부터 다시 찾는다**

### TYPE 표

| 값 | 이름 | 방향 | 응답 |
|---:|------|------|------|
| `0x01` | `HELLO` | ACU → RRU | `IDENT` |
| `0x02` | `IDENT` | RRU → ACU | — |
| `0x10` | `EVENT` | **RRU → ACU** | `EVENT_ACK` |
| `0x11` | `EVENT_ACK` | ACU → RRU | — |
| `0x20` | `OUTPUT` | ACU → RRU | `RESULT` |
| `0x21` | `OUTPUT_ALL` | ACU → RRU | `RESULT` |
| `0x30` | `PING` | ACU → RRU | `PONG` |
| `0x31` | `PONG` | RRU → ACU | — |
| `0x40` | `STATE_REQ` | ACU → RRU | `STATE` |
| `0x41` | `STATE` | RRU → ACU | — |
| `0x7F` | `RESULT` | 양방향 | — |

## 3. 연결 — 누구인지부터 밝힌다

ACU가 `/dev/ttyACM*`를 열면 **바로 `HELLO`를 보낸다.** RRU는 `IDENT`로 답한다.
**`IDENT`를 받기 전까지 ACU는 그 RRU의 이벤트를 받지 않는다** — 어느 모듈인지 모르기 때문이다.

### `HELLO` (0x01) — payload 없음

### `IDENT` (0x02) — 24byte

| 오프셋 | 크기 | 내용 |
|---:|---:|------|
| 0 | 1 | **프로토콜 판**. 지금 `0x01` |
| 1 | 1 | **RRU 번호** — DIP 스위치 값 **1~7** |
| 2 | 16 | **모델명** ASCII, 남는 자리는 `0x00` (`"RRU-M2"` / `"RRU-M4"`) |
| 18 | 4 | **펌웨어 판** `major.minor.patch.build` 각 1byte |
| 22 | 1 | 모듈 수 (`RRU-M2`=2, `RRU-M4`=4) — 모델명과 맞는지 ACU가 교차 확인 |
| 23 | 1 | 예약 `0x00` |

**ACU가 연결을 거부하는 경우** (로그를 남기고 RRU LED로 알린다):

```
· RRU 번호 0        스위치를 안 건드린 출하 상태(전부 OFF)
· RRU 번호 8~15     모듈 14칸을 넘는다
· RRU-M4에 번호 7   7·8을 써야 해 14칸을 넘는다
· 번호가 겹친다      먼저 붙은 쪽을 유지한다
· 모르는 모델명
· 모르는 프로토콜 판
```

### 모듈 번호는 ACU가 계산한다 — RRU는 몰라도 된다

```
DM 모듈 번호 = (RRU 번호 - 1) x 2 + 1  부터
  RRU-M2 : 모듈 2칸   RRU-M4 : 모듈 4칸 (번호 두 개를 쓴다)
```

RRU는 **자기 안의 리더·입력·출력 번호(1부터)** 만 쓴다. 모듈 번호로 옮기는 것은 ACU 몫이다.
**RRU 펌웨어에 모듈 번호 개념을 넣지 마십시오** — 설치 구성이 바뀌어도 RRU 펌웨어는 그대로여야 합니다.

## 4. 이벤트 — RRU가 먼저 보낸다

### `EVENT` (0x10) — 12 + M byte

| 오프셋 | 크기 | 내용 |
|---:|---:|------|
| 0 | 4 | **이벤트 ID** — RRU가 매기는 순번(빅엔디언, 1부터). 재전송 판별에 쓴다 |
| 4 | 1 | **종류** (아래) |
| 5 | 1 | **채널 번호** — RRU 안에서 1부터 (리더 1~8 / 입력 1~32 / 출력 1~16) |
| 6 | 1 | **값** — 종류마다 다름 |
| 7 | 4 | **RRU 기준 시각** (ms, 부팅 후 경과) — ACU가 순서·지연을 본다 |
| 11 | 1 | 뒤따르는 데이터 길이 M (카드면 카드 byte 수, 아니면 0) |
| 12 | M | 데이터 (카드 raw) |

| 종류 | 값 | 채널 | 값 필드 | 데이터 |
|---:|------|------|------|------|
| `0x01` | 카드 읽음 | 리더 번호 | Wiegand bit 수 (26/34/…) | 카드 raw (**큰 자리부터**) |
| `0x02` | 입력 변화 | 입력 번호 | 0=비활성 1=활성 | 없음 |
| `0x03` | 출력 상태 변화 | 출력 번호 | 0=꺼짐 1=켜짐 | 없음 |
| `0x04` | 리더 이상 | 리더 번호 | 0=정상 1=이상 | 없음 |
| `0x05` | 탬퍼 | 0 | 0=닫힘 1=열림 | 없음 |

- **카드 raw는 가공하지 마십시오.** Wiegand에서 읽은 비트를 **큰 자리부터 byte로 채워** 그대로 올립니다.
  패리티 처리·시설 코드 분리는 **ACU가 합니다** (리더 종류·Wiegand 형식이 DM 설정에서 오기 때문)
- **입력은 변화할 때만** 보냅니다 (0→1, 1→0). 주기 보고는 하지 않습니다
- 채터링은 **RRU가 거릅니다** — 기본 디바운스 **50ms** 제안. 이 값은 실측 후 정합니다

### `EVENT_ACK` (0x11) — 4byte

| 오프셋 | 크기 | 내용 |
|---:|---:|------|
| 0 | 4 | 받았다고 확인하는 **이벤트 ID** (그 ID까지 전부 받았다는 뜻) |

### ⚠ 이벤트는 ACK를 받을 때까지 RRU가 들고 있습니다

USB가 끊기면 그 사이 카드 태그가 사라집니다. **출입 기록은 사후 증거**라 그러면 안 됩니다.

```
RRU 안에 이벤트 버퍼 (제안: 최소 64건, 가능하면 256건)
  1. 이벤트가 생기면 버퍼에 넣고 ID를 매긴다
  2. 링크가 살아 있으면 보낸다
  3. EVENT_ACK를 받은 ID까지만 버퍼에서 지운다
  4. 링크가 끊겼다 붙으면 HELLO/IDENT 뒤에 **안 지운 것부터 다시 보낸다**
  5. 버퍼가 가득 차면 가장 오래된 것을 버리고 로그를 남긴다
```

- **ID는 재연결해도 이어집니다** (RRU 부팅 때만 1로 돌아갑니다). ACU가 겹침을 걸러 냅니다
- ACU는 같은 ID를 두 번 받으면 **뒤엣것을 버립니다** — 잃는 것보다 겹치는 편이 낫습니다

## 5. 출력 — ACU가 시킨다

RRU는 **스스로 릴레이를 움직이지 않습니다.** 문 열기도, 알람 울리기도 전부 ACU 명령입니다.
(입력→출력 연동 판단은 DM 설정을 아는 ACU만 할 수 있습니다)

### `OUTPUT` (0x20) — 4byte

| 오프셋 | 크기 | 내용 |
|---:|---:|------|
| 0 | 1 | 출력 번호 (1부터) |
| 1 | 1 | 동작 `0`=끄기 `1`=켜기 `2`=시간만큼 켜기 |
| 2 | 2 | 시간 (0.1초 단위, 동작 2일 때만. 예: `30` = 3.0초) |

### `OUTPUT_ALL` (0x21) — 4byte

여러 출력을 **한 프레임에** 움직입니다. 알람·화재 때 "동작 종류 Alarm인 출력 전부"를
한꺼번에 켜야 하는데, 한 개씩 보내면 사람이 느낄 만큼 시차가 납니다.

| 오프셋 | 크기 | 내용 |
|---:|---:|------|
| 0 | 2 | **출력 비트맵** (bit 0 = 출력 1 … bit 15 = 출력 16) |
| 2 | 1 | 동작 (위와 같음) |
| 3 | 1 | 시간 (0.1초 단위) |

### `RESULT` (0x7F) — 2byte

| 오프셋 | 크기 | 내용 |
|---:|---:|------|
| 0 | 1 | `0`=성공 `1`=모르는 명령 `2`=잘못된 인자 `3`=장치 오류 |
| 1 | 1 | 원래 명령의 TYPE |

- **시간만큼 켜기는 RRU가 끕니다** — ACU가 두 번 명령하지 않아도 되고, 그 사이 링크가 끊겨도
  문이 계속 열려 있지 않습니다. 이건 "자율 구동"이 아니라 **명령의 일부**입니다

## 6. 살아 있는지 — `PING` / `PONG`

- ACU가 **2초마다** `PING`(payload 없음)을 보냅니다
- RRU는 곧바로 `PONG`(payload 없음, 같은 SEQ)으로 답합니다
- **`PONG`이 3번 연속 오지 않으면** ACU가 그 RRU를 끊긴 것으로 봅니다 (약 6초)
  → DM에 **USB 단절 이벤트 `0x20030102`** 를 올립니다 (그 RRU의 첫 모듈 번호, 리더 0)
  → 포트를 닫고 다시 엽니다
- **복구는 DM에 올리지 않습니다** (2026-09-11 Platinum 회신 — 기존 장비가 그렇습니다)

> `PING`이 필요한 이유: USB 케이블이 빠지면 커널이 알려 주지만, **RRU 펌웨어가 멈춘 경우**는
> 노드가 그대로 살아 있어 읽기만 조용해집니다. 그건 조용한 것으로만 알 수 있습니다.

## 7. 상태 조회 — `STATE_REQ` / `STATE`

ACU가 재연결 직후 **지금 입력이 어떤 상태인지** 한 번에 확인합니다.
(변화만 보내는 구조라, 끊긴 사이에 바뀐 것을 이걸로 맞춥니다)

### `STATE` (0x41) — 8byte

| 오프셋 | 크기 | 내용 |
|---:|---:|------|
| 0 | 4 | 입력 비트맵 (bit 0 = 입력 1 … bit 31 = 입력 32) |
| 4 | 2 | 출력 비트맵 (bit 0 = 출력 1 … bit 15 = 출력 16) |
| 6 | 1 | 리더 이상 비트맵 (bit 0 = 리더 1 …) |
| 7 | 1 | 탬퍼 `0`/`1` |

## 8. 시작 절차 (ACU 쪽에서 본 순서)

```
1. /dev/ttyACM* 가 생긴다            (udev)
2. 열고 HELLO                        재시도 3회, 각 500ms
3. IDENT 받음                        번호·모델 확인, 거부 조건 검사
4. STATE_REQ -> STATE                지금 입력 상태를 맞춘다
5. 밀린 EVENT 를 받는다               ACK 안 된 것부터 (RRU가 알아서 보낸다)
6. 정상 운전                          EVENT(RRU->ACU) / OUTPUT(ACU->RRU) / PING 2초
```

## 9. 시리얼 포트 설정

| 항목 | 값 |
|------|-----|
| 속도 | CDC-ACM이라 **의미 없음** (아무 값이나 무시됨). ACU는 `B115200`으로 열되 의존하지 않는다 |
| 형식 | 8N1, 흐름 제어 없음 |
| 모드 | **raw** (`cfmakeraw`) — 줄바꿈 변환·에코·시그널 전부 끔 |
| 노드 이름 | `/dev/ttyACM*`는 **번호가 바뀝니다** → ACU는 udev 규칙으로 **고정 이름**을 만들어 씁니다 |

⚠ RRU 쪽 **USB 시리얼 번호(iSerialNumber)를 RRU 번호나 고유값으로 채워 주십시오.**
그래야 udev로 안정적인 이름을 붙일 수 있습니다. 비어 있으면 여러 대를 구분하기 어렵습니다.

## 9-1. 타이밍 — 숫자를 한곳에

| 항목 | 값 | 누가 | 비고 |
|------|---:|------|------|
| `HELLO` 재시도 | 3회, 간격 **500ms** | ACU | 다 실패하면 포트를 닫고 2초 뒤 다시 연다 |
| `IDENT` 대기 | **500ms** | ACU | 넘기면 재시도로 친다 |
| `PING` 주기 | **2초** | ACU | |
| `PONG` 대기 | **500ms** | ACU | 이 안에 안 오면 1회 실패 |
| 단절 판정 | `PONG` **3회 연속** 실패 (약 6초) | ACU | DM에 `0x20030102` |
| 재연결 시도 | 단절 뒤 **2초**마다 | ACU | 붙을 때까지 |
| 명령 응답(`RESULT`) | **200ms** 안에 | **RRU** | 늦으면 ACU가 다시 보낸다 |
| 같은 명령 재전송 | 2회까지 | ACU | 그래도 없으면 `PONG` 실패와 같게 센다 |
| 입력 디바운스 | **50ms** (제안) | **RRU** | 실측 후 확정 |
| 이벤트 올림 | 생기는 즉시 | **RRU** | 모아 보내지 않는다 |

⚠ **RRU는 명령을 받으면 200ms 안에 답해야 합니다.** 릴레이를 실제로 붙이는 데 시간이 걸리면
**먼저 `RESULT`로 "받았다"를 답하고** 동작하십시오. 동작 결과는 `EVENT`(출력 상태 변화)로 따로 올라옵니다.

## 9-2. 상태 기계

### ACU가 보는 RRU 하나

```
        포트 없음
           |  udev가 노드를 만든다
           v
      [ 여는 중 ] --열기 실패--> 2초 뒤 재시도
           |  열림 -> HELLO
           v
      [ 식별 중 ] --3회 실패--> 포트 닫고 [ 여는 중 ]
           |  IDENT 받음 (번호·모델 확인)
           |       \--거부 조건--> 포트 닫고 로그·LED, 다시 열지 않는다
           v
      [ 맞추는 중 ] STATE_REQ -> STATE, 밀린 EVENT 받기
           |
           v
      [ 운전 ] <---------------+
           |  PONG 3회 실패     |  PONG 정상
           v                    |
      [ 단절 ] --2초마다 재시도--+
         DM에 0x20030102 (한 번만)
```

- **[운전]에 들어가기 전에는 카드 이벤트를 판정에 쓰지 않습니다** — 어느 모듈인지 모르기 때문입니다
- **단절 이벤트는 한 번만** 올립니다. 재연결해도 복구 이벤트는 올리지 않습니다(기존 장비가 그렇습니다)

### RRU 쪽

```
      [ 부팅 ] DIP 읽기, 이벤트 ID = 1, 버퍼 비움
           |  USB 열거됨
           v
      [ 대기 ] --HELLO--> IDENT 보내고 [ 운전 ]
           |
           +-- 이벤트가 생기면 **버퍼에 넣는다** (링크가 없어도)
           v
      [ 운전 ] 이벤트 보냄 / EVENT_ACK 받으면 버퍼에서 지움
           |  USB 끊김(suspend·재열거)
           v
      [ 대기 ]  **버퍼와 이벤트 ID는 그대로 둔다**
```

⚠ **RRU는 재열거로 다시 붙어도 이벤트 ID를 1로 되돌리지 않습니다.** 전원이 꺼졌다 켜졌을 때만 1입니다.
그래야 ACU가 "이건 아까 그거"를 알아봅니다.

## 9-3. 오류가 났을 때

| 상황 | 받는 쪽이 하는 일 |
|------|------------------|
| CRC 불일치 | **조용히 버린다.** 답하지 않는다 — 보낸 쪽의 타임아웃이 처리한다 |
| `LEN`이 최대(255)를 넘음 | 버리고 **다음 `STX`부터 다시 찾는다** |
| `ETX` 자리가 `0x03`이 아님 | 위와 같다 |
| 모르는 `TYPE` | `RESULT`(코드 1 = 모르는 명령)로 답한다. **끊지 않는다** |
| 인자가 범위를 벗어남 (예: 출력 99번) | `RESULT`(코드 2 = 잘못된 인자) |
| 장치가 실제로 실패 (릴레이 고장 등) | `RESULT`(코드 3 = 장치 오류) |
| `IDENT` 전에 온 명령 | RRU는 `IDENT`만 보내고 나머지는 무시한다 |
| 중간에 끊긴 프레임 | **`LEN`만큼 안 오면 버린다.** 200ms 안에 다 안 오면 그 프레임을 포기한다 |

**되풀이해서 잘못된 프레임이 온다면** — 양쪽 모두 로그만 남기고 링크를 끊지 않습니다.
끊으면 재열거가 돌고, 그게 더 큰 문제를 만듭니다.

> **왜 CRC 불일치에 답하지 않는가**: 깨진 프레임은 `SEQ`도 믿을 수 없어 **무엇에 답하는지 알 수 없습니다.**
> 잘못 답하면 보낸 쪽이 다른 명령의 응답으로 오해합니다.

## 9-4. 메시지별 byte 예시 (전부)

`xx xx`는 CRC 자리입니다. `LEN`은 `SEQ + TYPE + PAYLOAD`를 셉니다.

```
HELLO      ACU->RRU   02 00 02 01 01 xx xx 03
                      STX LEN=2 SEQ=1 TYPE=01                      (payload 없음)

IDENT      RRU->ACU   02 00 1A 01 02 | 01 01 52 52 55 2D 4D 32 00.. | 01 00 00 05 | 02 00 | xx xx 03
                      LEN=26 SEQ=1 TYPE=02
                      판=01  RRU번호=01  모델="RRU-M2"(16byte)
                      펌웨어 1.0.0.5     모듈수=02  예약=00

EVENT      RRU->ACU   02 00 16 07 10 | 00 00 00 2A | 01 02 1A | 00 01 86 A0 | 08 |
                      00 00 00 00 02 06 5D C1 | xx xx 03
                      LEN=22 SEQ=7 TYPE=10
                      이벤트ID=42  종류=01(카드) 리더=02 26bit  시각=100,000ms  M=8  카드 raw

EVENT_ACK  ACU->RRU   02 00 06 07 11 00 00 00 2A xx xx 03
                      LEN=6 SEQ=7 TYPE=11  "42번까지 받았다"

OUTPUT     ACU->RRU   02 00 06 0C 20 01 02 00 1E xx xx 03
                      LEN=6 SEQ=12 TYPE=20  출력1  동작2(시간만큼)  3.0초

OUTPUT_ALL ACU->RRU   02 00 06 0D 21 00 0F 01 00 xx xx 03
                      LEN=6 SEQ=13 TYPE=21  비트맵 000F(출력 1~4)  동작1(켜기)  시간 무시

RESULT     RRU->ACU   02 00 04 0C 7F 00 20 xx xx 03
                      LEN=4 SEQ=12 TYPE=7F  결과 0(성공)  원래 TYPE=20

PING       ACU->RRU   02 00 02 20 30 xx xx 03
PONG       RRU->ACU   02 00 02 20 31 xx xx 03      **요청과 같은 SEQ**

STATE_REQ  ACU->RRU   02 00 02 21 40 xx xx 03
STATE      RRU->ACU   02 00 0A 21 41 | 00 00 00 05 | 00 03 | 00 | 00 | xx xx 03
                      LEN=10 SEQ=33 TYPE=41
                      입력비트맵 00000005(입력1·3 활성) 출력비트맵 0003(출력1·2 켜짐)
                      리더이상 00  탬퍼 00
```

## 9-5. RRU 쪽 참조 코드

받는 부분만 있으면 나머지는 쉽습니다. **그대로 쓰셔도 되고 참고만 하셔도 됩니다.**

```c
/* 프레임 받기 — 한 byte씩 넣으면 완성될 때 1을 돌려준다 */
#define RRU_MAX_PAYLOAD 255
#define RRU_FRAME_MAX   (1 + 2 + 2 + RRU_MAX_PAYLOAD + 2 + 1)

typedef struct {
    uint8_t buf[RRU_FRAME_MAX];
    uint16_t len;       /* 지금까지 모은 byte 수 */
    uint16_t want;      /* 프레임 전체 길이 (헤더를 읽으면 정해진다) */
} RruRx;

/* 반환: 1 = 프레임 하나 완성 (buf[3]=TYPE, buf+4=payload), 0 = 더 필요 */
static int rru_rx_byte(RruRx *r, uint8_t b)
{
    if (r->len == 0) {
        if (b != 0x02) return 0;          /* STX를 찾을 때까지 버린다 */
        r->buf[r->len++] = b;
        r->want = 0;
        return 0;
    }

    r->buf[r->len++] = b;

    if (r->len == 3) {                     /* LEN 두 byte를 다 읽었다 */
        uint16_t body = (uint16_t)(r->buf[1] << 8 | r->buf[2]);
        if (body < 2 || body > 2 + RRU_MAX_PAYLOAD) { r->len = 0; return 0; }
        r->want = (uint16_t)(3 + body + 3);   /* STX+LEN(3) + body + CRC(2)+ETX(1) */
    }

    if (r->want == 0 || r->len < r->want) return 0;

    /* 다 왔다 — CRC와 ETX를 본다 */
    uint16_t body = (uint16_t)(r->want - 6);
    uint16_t got  = (uint16_t)(r->buf[3 + body] << 8 | r->buf[3 + body + 1]);
    int ok = (r->buf[r->want - 1] == 0x03) && (got == rru_crc16(&r->buf[3], body));

    r->len = 0;                            /* 성공이든 실패든 다음 프레임을 기다린다 */
    return ok;                             /* 실패면 조용히 버린 것이 된다 */
}
```

```c
/* 프레임 보내기 */
static uint16_t rru_build(uint8_t *out, uint8_t seq, uint8_t type,
                          const uint8_t *payload, uint8_t n)
{
    uint16_t body = (uint16_t)(2 + n);
    out[0] = 0x02;
    out[1] = (uint8_t)(body >> 8);
    out[2] = (uint8_t)body;
    out[3] = seq;
    out[4] = type;
    if (n) memcpy(out + 5, payload, n);

    uint16_t crc = rru_crc16(out + 3, body);
    out[3 + body]     = (uint8_t)(crc >> 8);
    out[3 + body + 1] = (uint8_t)crc;
    out[3 + body + 2] = 0x03;
    return (uint16_t)(3 + body + 3);
}
```

> **이 코드와 9-4의 예시는 검산했습니다** — `tools/rru_proto_check.c`
> (`make -C acud rrucheck && ./acud/rru_proto_check`). 문서에 적은 코드를 그대로 복사해 넣고
> CRC 검사값, 메시지별 전체 길이(= 8 + payload), 파서의 네 가지 경우
> (정상 / payload에 `STX`·`ETX` 포함 / CRC 훼손 / 깨진 프레임 뒤 회복)를 봅니다.

⚠ **`rru_rx_byte()`는 `STX`가 payload 안에 나와도 안전합니다** — `LEN`만큼 모은 뒤에 판단하기 때문입니다.
CRC가 틀리면 버리고 **그다음 byte부터 다시 `STX`를 찾습니다.**

## 9-6. 적합성 확인 목록 (RRU 펌웨어 완성도 자가 점검)

개발보드가 오면 이 순서로 맞춰 보겠습니다. **위에서부터** 하나씩입니다.

| # | 확인할 것 | 어떻게 |
|---|-----------|--------|
| 1 | USB CDC-ACM으로 열거된다 | ACU에서 `/dev/ttyACM*`가 생긴다 |
| 2 | `iSerialNumber`가 채워져 있다 | `udevadm info`로 본다 |
| 3 | `HELLO`에 `IDENT`로 답한다 | 500ms 안에, 24byte |
| 4 | DIP 번호가 `IDENT`에 맞게 실린다 | 스위치를 1→2로 바꾸고 재부팅해 확인 |
| 5 | CRC가 맞다 | 일부러 틀린 CRC를 보내면 **답하지 않는다** |
| 6 | 모르는 `TYPE`에 `RESULT`(1)로 답한다 | 끊지 않는다 |
| 7 | 카드 태그가 `EVENT`로 올라온다 | 카드 raw가 **가공 없이** 큰 자리부터 |
| 8 | `EVENT_ACK` 전에는 버퍼에 남는다 | ACK를 일부러 늦춰 본다 |
| 9 | **USB를 뽑았다 꽂으면 밀린 이벤트가 다시 온다** | 뽑은 채로 카드 3장 → 꽂고 3건이 오는지 |
| 10 | 이벤트 ID가 재연결해도 이어진다 | 위 9번에서 ID가 1로 안 돌아가는지 |
| 11 | 입력 변화가 `EVENT`로 온다 | 채터링이 걸러지는지 함께 본다 |
| 12 | `OUTPUT` 시간만큼 켜기가 **RRU에서 꺼진다** | 3초 명령 뒤 USB를 뽑아도 3초에 꺼지는지 |
| 13 | `OUTPUT_ALL` 비트맵이 동시에 동작한다 | 오실로스코프 또는 눈으로 |
| 14 | `PING`에 200ms 안에 `PONG` | 같은 SEQ로 |
| 15 | `STATE`가 지금 상태와 맞다 | 입력을 바꿔 놓고 `STATE_REQ` |
| 16 | 릴레이를 켜도 USB가 안 끊긴다 | **가장 중요합니다** — 8개 동시에 여러 번 |

⚠ **16번이 이 프로토콜을 만든 이유입니다.** 그래도 끊긴다면 9~10번이 그 피해를 막아 줍니다.

## 10. 🔴 RRU 쪽에 확인·결정이 필요한 것

| # | 내용 | 왜 |
|---|------|-----|
| 1 | **이벤트 버퍼를 몇 건까지 둘 수 있습니까** | 제안 64~256건. RAM 여유에 달렸습니다 |
| 2 | **디바운스 50ms가 적당합니까** | 실제 입력 장치로 재 봐야 압니다 |
| 3 | **USB 시리얼 번호를 채울 수 있습니까** | 여러 대 구분에 필요합니다 (9절) |
| 4 | **Wiegand 비트 수를 그대로 올릴 수 있습니까** | 26/34 외 형식도 ACU가 처리하려면 필요합니다 |
| 5 | **DIP 스위치를 부팅 때만 읽습니까, 계속 읽습니까** | 운전 중 번호가 바뀌면 ACU가 혼란스럽습니다 — **부팅 때만** 읽기를 권합니다 |
| 6 | **VBUS/GND 처리** | RRU가 자체 전원이라 VBUS를 연결할지 말지 정해야 합니다 |
| 7 | **`OUTPUT_ALL` 비트맵 16칸으로 충분합니까** | `RRU-M4`가 출력 16개라 딱 맞습니다. 더 늘어날 계획이 있으면 알려 주십시오 |
| 8 | **펌웨어 갱신을 이 링크로 할 계획입니까** | 있다면 TYPE을 미리 비워 두겠습니다 (`0x50~0x5F` 예약 제안) |

## 11. 아직 정하지 않은 것 (다음 판)

- **펌웨어 갱신** — 위 8번 답에 따라
- **시각 동기** — 지금은 RRU가 부팅 후 경과 ms만 올리고 절대 시각은 ACU가 붙입니다.
  RRU에 RTC를 넣을 계획이 없다면 이대로 두는 것이 맞습니다
- **암호화·인증** — 같은 함체 안 짧은 배선이라 지금은 넣지 않습니다
- **생체 인식 장치** — 별도 망·별도 프로그램입니다 (이 링크에 섞지 않습니다)

## 부록 A. CRC-16/CCITT-FALSE

```c
uint16_t rru_crc16(const uint8_t *p, uint16_t n)
{
    uint16_t crc = 0xFFFF;
    for (size_t i = 0; i < n; i++) {
        crc ^= (uint16_t)p[i] << 8;
        for (int b = 0; b < 8; b++)
            crc = (crc & 0x8000) ? (uint16_t)((crc << 1) ^ 0x1021) : (uint16_t)(crc << 1);
    }
    return crc;
}
```

검사값: `"123456789"` → `0x29B1`
